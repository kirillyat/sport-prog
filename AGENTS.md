# Инструкции для агентов

Этот файл читают Codex и Cursor напрямую, Claude Code — через `CLAUDE.md`.
Навыки лежат в `.claude/skills/`; Codex находит их по ссылке `.agents/skills`,
Cursor и Claude Code — на месте.

Портал тренировок по программированию: один процесс FastAPI + SQLite в томе.
Ни Postgres, ни Redis, ни воркеров, ни фронтенд-сборки — это осознанно, а не
«ещё не дошли руки». Преподаватель выдаёт задания с LeetCode, Codeforces и
свои задачи с проверкой judge0; студенты решают, портал считает зачёт.

## С кем ты работаешь

С порталом работают двое, и задачи у них разные. Пойми по просьбе, кто перед
тобой, — от этого зависит, какой навык брать.

**Разработчик** правит сам портал: код, шаблоны, миграции, выкатку.

**Преподаватель** готовит курс: подбирает задачи, пишет условия и тесты,
проводит контрольные, пишет объявления студентам. Код портала ему нужен
редко; ему нужны архив задач, текст для группы и ответ «почему студент не
видит задание». То, что делается в интерфейсе портала (загрузить набор,
выдать задание, подключить судью), делает он сам — ты готовишь и объясняешь.

## Навыки

| Навык | Для кого | Когда |
|---|---|---|
| `local-portal` | разработчик | поднять портал у себя и проверить правку глазами, с поддельным судьёй |
| `i18n` | разработчик | новая строка интерфейса, новый язык |

| `pick-problems` | преподаватель | подобрать задачи под пройденные темы, с метками и уровнем |
| `task-set` | преподаватель | условие, тесты, эталон, проверка и архив своих задач |
| `exam` | преподаватель | провести контрольную: список, судья, выдача, письмо группе |

В рабочем репозитории экземпляра бывают ещё навыки с приставкой `msu-` — про
конкретный стенд: сервер и выкатку, судью, курс, людей. В открытую копию они
не уезжают. Если они есть — для вопросов про прод бери их.

## Команды

```bash
ruff check app tests scripts migrations    # линтер
pytest -q                                  # тесты, их 400+
python scripts/i18n_sync.py                # собрать строки интерфейса в словари
python scripts/publish_github.py           # открытая копия на GitHub
alembic upgrade head                       # миграции; путь к базе берётся из DATA_DIR
```

Локальный запуск: `DEV_LOGIN_ENABLED=true` в `.env` даёт вход по имени без
Telegram и OIDC. Первый вошедший становится преподавателем — иначе портал
запирается, потому что переключатель ролей лежит за ролью преподавателя.
Подробно — навык `local-portal`.

Инструменты разработки живут в `[dependency-groups]` (PEP 735), а не в extras:
`pip install -e ".[dev]"` их **не поставит**, ставь `pytest pytest-asyncio ruff`
отдельно.

В git worktree с общим окружением запускай с `PYTHONPATH=$PWD`: пакет стоит
в editable-режиме из основного чекаута, и без этого `pytest` молча проверяет
не твой код.

## Как здесь принято писать

- **Комментарий объясняет причину, а не действие.** Если из кода видно «что»,
  комментарий нужен только про «почему». Половина комментариев в проекте —
  это защита от правки, которая выглядит улучшением, но ломает смысл.
- **Тест формулирует правило.** Имя теста — утверждение
  (`test_rejected_solution_removes_the_credit`), а не «проверка функции X».
  Новый тест сначала должен упасть на старом коде — иначе он ничего не ловит.
- **Русский язык** в коде, комментариях и коммитах. Смешивать хуже, чем
  выбрать один.
- **Без инлайнового JavaScript.** Скрипты лежат в `app/static`, строки для них
  приезжают данными через `<script type="application/json">`.
- **Без новых зависимостей**, пока не исчерпаны стандартная библиотека и то,
  что уже стоит. Чужие файлы (CodeMirror, шрифты) лежат у нас вместе с
  лицензиями, без CDN: портал работает и в аудитории без интернета.

## Что легко сломать

**Зачёт считается в одном месте** — `Cell.counts` в `app/services/progress.py`:
решено в срок, код прислан (если задание требует) и не отклонён. Табло, матрица
преподавателя и выгрузка в CSV спрашивают у него. Если добавляешь новое место,
где «сколько решено», — спрашивай там же, иначе портал начнёт показывать разные
цифры на разных страницах, и цифрам перестанут верить.

**Доступ к заданию считается в одном месте** — `may_see_assignment` рядом со
списком заданий. Когда страница задания считала по-своему, задание «всем»
висело у студента в списке и не открывалось. Преподавателя проверки доступа
пропускают — проверяй под студентом.

**Закрытые тесты не покидают портал** — ни вводом, ни ответом, ни выводом
решения, ни потоком ошибок. `print(input(), file=sys.stderr)` выдал бы тест
целиком; судья отдаёт `stdout`/`stderr` только по открытым тестам.

**Код студента не теряется.** Студент пишет решение прямо в редакторе:
поле с кодом лежит внутри формы, черновик привязан к задаче, а не к адресной
строке. Любой путь отказа (судья молчит, попытки кончились) возвращает
страницу с кодом.

**Решения преподавателя студентам не видны** — ни в ленте, ни в табло, ни в
профиле: преподаватель прорешивает задачи контрольной заранее.

**Интерфейс переводится.** Новая строка оборачивается в `_("…")`, константы
модулей — в `N_("…")` (они собираются при импорте, когда язык ещё неизвестен).
Дальше `python scripts/i18n_sync.py` и заполнение `app/locales/*.json`. Тесты
следят, чтобы подстановки `%(count)s` не потерялись и чтобы форм слова было
столько, сколько знает язык.

**Содержимое не лежит в исходниках.** Логотип вуза — в томе данных
(`DATA_DIR/branding`), материалы курса — в `course/` и в открытую копию не
уезжают. Проверяй, что портал работает без них: разделы просто скрываются.
`scripts/sync_course.py` стирает `course/` целиком — своё там не храни.

**Миграции необратимы на проде.** Откат кода не откатывает схему. Миграцию,
которая трогает существующие данные, сначала прогоняют на копии боевой базы.

## Прод

- Выкатка, запись в боевую базу, письма студентам — только по явному «да» в
  этом разговоре. Согласие на прошлую выкатку следующую не покрывает.
- Боевую базу без нужды не читай: там имена и результаты студентов.
  Диагностика — короткими командами на чтение.
- Адреса, имена и порядки конкретного стенда — только в навыках `msu-*`.
  `AGENTS.md`, `CLAUDE.md` и остальные навыки уезжают в открытую копию.
