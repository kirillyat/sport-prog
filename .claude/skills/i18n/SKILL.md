# Строки интерфейса

Исходный язык — русский: **строка в шаблоне и есть ключ словаря**. Перевода
нет — показывается русский исходник, страница не ломается. Поэтому gettext
с компиляцией `.mo` не нужен, словари — обычный JSON.

## Новая строка

1. В шаблоне: `{{ _("Прислать код") }}`; в питоне: `from app.i18n import translate as _`.
2. Константы модулей (списки разделов, месяцы, подписи статусов) помечаются
   `N_("…")`: они собираются при импорте, когда язык запроса ещё неизвестен,
   а переводятся при выводе — `_(section.title)`.
3. Собрать и заполнить:
   ```bash
   python scripts/i18n_sync.py     # покажет, сколько строк без перевода
   ```
   Пустое значение в `app/locales/en.json` и `fr.json` — это «перевода нет».
4. `pytest -q` — тесты проверяют, что подстановки `%(count)s` не потерялись
   и что форм слова столько, сколько знает язык.

## Подстановки и формы слова

Собирай фразу целиком, а не из кусков: порядок слов в языках разный.

```python
_("%(count)s %(unit)s назад") % {"count": n, "unit": plural(n, _("минуту|минуты|минут"))}
```

Формы через `|`: три у русского, две у английского и французского. Правило
выбирается по текущему языку — `plural` в `app/templating.py`, `portalPlural`
в `app/static/i18n.js`.

## Строки для скриптов

Инлайнового JS на страницах нет. Строки уезжают данными: `js_strings()`
в `app/templating.py` → `<script type="application/json">` в `base.html` →
`app/static/i18n.js`. Новая строка для скрипта добавляется в `js_strings()`.

## Новый язык

1. Код и самоназвание в `LANGUAGES` (`app/i18n.py`).
2. `python scripts/i18n_sync.py` создаст словарь.
3. Правило множественного числа — в `plural` и `portalPlural`.
4. Язык по умолчанию для тех, кто ничего не выбрал, — `DEFAULT_LANGUAGE` в `.env`.

## Ловушка

В Jinja фильтр сильнее `%`: `_("…") % {…} | safe` разберётся как
`_("…") % ({…} | safe)` и упадёт «format requires a mapping». Пиши скобки:
`(_("…") % {…}) | safe`.
