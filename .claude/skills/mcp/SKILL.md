# Портал для нейросетей

Три слоя, и у каждого одна забота:

| Файл | Что там |
|---|---|
| `app/mcp/tools.py` | инструменты: что видно и что делается, описание для модели |
| `app/mcp/registry.py` | реестр, роли, ключ на запись, раздел «ИИ», проверка параметров |
| `app/mcp/server.py` | JSON-RPC по HTTP на `/mcp`, оба поколения протокола |

Ключи — `app/services/api_tokens.py`, страница — `app/routers/ai.py` и
`templates/ai.html`. Реестр от транспорта не зависит: встроенная модель
портала будет звать `registry.call` напрямую, поэтому права проверяются
в реестре, а не в `server.py`.

## Новый инструмент

1. **Сначала сервис.** Если правило живёт в обработчике формы
   (`app/routers/…`), вынеси его в `app/services/…` и переведи страницу на
   него же. Инструмент, который считает по-своему, — это две правды:
   так табло однажды уже разошлось с матрицей.
2. Параметры — подкласс `Params` (лишние поля запрещены, модель узнаёт
   об опечатке сразу). У поля — `description`: его читает модель.
3. Функция с `@tool("имя", title=N_("…"), hint=N_("…"),
   roles=STUDENT|TEACHER, writes=…, notifies=…)`. Докстрока — описание для
   модели: что вернёт, когда звать, что сказать человеку до вызова. `hint` —
   строка для человека на странице «ИИ»: что инструмент даёт и чего не даст. `writes=True` — нужен ключ
   «с изменениями»; `notifies=True` — действие видно снаружи (Telegram).
4. Отказ — `raise ToolError("…")`: модель увидит причину и исправится.
   Чужое студенту отвечай как «не найдено», не «нельзя».
5. Связи моделей (`assignment.group`, `problem_set.items`) не трогай: у
   только что созданных объектов они не загружены, а ленивая подгрузка
   в асинхронной сессии падает. Нужное — отдельным запросом
   (`_group_titles`, `problems_for_set`).
6. Тест в `tests/test_mcp.py`: правило именем теста, проверка под
   студентом, если инструмент студенческий. Подпись `title` — в словари:
   `python scripts/i18n_sync.py`, её показывает страница «ИИ».

Студенту — только своё и только чтение. Закрытые тесты, чужие решения и
решения преподавателя не уходят никому.

## Проверить руками

Поднять портал (навык `local-portal`), на `/ai` выпустить ключ, затем:

```bash
curl -s localhost:8000/mcp -H "Authorization: Bearer $KEY" \
  -H 'Content-Type: application/json' \
  -d '{"jsonrpc":"2.0","id":1,"method":"tools/list"}'
```

Или подключить настоящий клиент по инструкции со страницы «ИИ»
(`claude mcp add --transport http …`) и попросить его что-нибудь сделать.

## Протокол

- До 2025-11-25 клиент начинает с `initialize`; сессий не выдаём — они
  необязательны, а состояния между вызовами у нас нет.
- С 2026-07-28 рукопожатия нет: версия в `_meta` каждого запроса,
  заголовки `MCP-Protocol-Version`, `Mcp-Method`, `Mcp-Name` обязаны
  совпадать с телом (иначе 400 и `-32020`). Новую ревизию спецификации —
  в `MODERN_VERSIONS`, прочитав её changelog.
- Входа по OAuth нет: клиенты, которые умеют только его (ChatGPT,
  claude.ai в браузере), не подключатся. Это следующий шаг, не ошибка.

## «Клиент не подключается»

- 401 — ключа нет в заголовке или его отозвали. Куку сайта `/mcp` не
  принимает нарочно.
- 403 «раздел закрыт» — «ИИ» закрыт этой роли в «Видимости разделов».
- 403 без текста — браузерный `Origin` не совпал с `BASE_URL`.
- У преподавателя нет `create_problem_set` и `create_assignment` — ключ
  выпущен на чтение; или роль у человека сняли, и он видит студенческое.
